# Memory Index

This file is auto-loaded on cold-start; only the **Hot** section is guaranteed inside the auto-load
window. **Cold** entries are one `Read` away — reading a file reinforces it (bumps its score, grows
its stability) and the next rerank may promote it. Lower-relevance entries beyond the Cold budget
roll off to `MEMORY-archive.md` (a full catalog, also one `Read` away) — topic files are **never
deleted**, only their index visibility shifts.

Ranking (two-strength model): `(access_count + 1) * exp(-days_since_last_access / stability) + 0.6 *
importance`, where `stability` grows with spaced reinforcement and `importance` (0-10, default 0) is
a non-decaying floor for critical memories. Regenerated by `executions/rerank_memory_index.py`; do
not hand-edit the tables (curated row summaries are preserved across regenerations).

## How to Use

1. **Cold-start (in order):**
   1. Read `current-state.md` — what's happening *now*.
   2. Glob `short-term/*.md` for the last 7 days (T1 episodic facts + session residue).
   3. Scan the **Hot** table; open only the topic files your task needs.
   4. If a topic isn't in Hot, check **Cold** (or grep the memory dir) — cold entries are not gone,
      just one explicit `Read` away. Reading bumps the score; the next rerank may re-promote.
2. **Adding knowledge**: append to the appropriate existing topic file. If no topic fits, create a
   new one — the next rerank adds its row automatically.
3. **T0/T1/T2/T3/T4**: see the two-axis memory model in the repo `README.md`. Promotion into the
   lens tiers (T3/T4) is always a deliberate human action, never automatic.
