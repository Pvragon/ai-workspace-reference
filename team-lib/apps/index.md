# apps

## Purpose
Human-facing workspace applications. An app is something a **person** launches and uses
directly: a terminal UI, a pane on a desktop wall, a small desktop tool. Agents may help build
and maintain them, but the user of an app is a human sitting at the keyboard.

## What Belongs Here
- Terminal UIs, desktop panes and other interactive tools a person runs by hand
- Apps that are generic enough for any teammate's workspace (no hardcoded home paths,
  no personal data; per-user state lives under `~/.config/<app>/`)

## What Does NOT Belong Here
Each boundary has a one-line test.

| Goes elsewhere | Test | Home |
|---|---|---|
| **Project code** | Does it belong to one product, client or deliverable, with its own repo, specs or release cycle? | `projects/` |
| **Integrations** | Is it a CLI, MCP server or service bridge that an **agent** drives to reach an external system? | `integrations/` |
| **Executions** | Is it a deterministic script an **agent** calls, with a `run()` entry point and no interactive UI? | `executions/` (must follow [execution-standard.md](../context/indexed/execution-standard.md)) |

If a human is the one using it, interactively, as part of their workspace, it is an app.

## What Each App Folder Must Contain
One folder per app, `apps/<app-name>/` in `kebab-case`:

- **The app itself**: its entry point and any source files. Python entry points carry the
  `# ---` comment-block frontmatter (`template: app`, `version`, `summary`, `created`,
  `last_updated`, `maintainer`).
- **`README.md`** written for humans: what it does, install steps per platform, how to run it,
  keys or usage, and platform support. It carries standard `---` YAML frontmatter; its
  `summary:` is the row shown in the table below.
- **Example config, never real config**: e.g. `channels.example.txt`. A person's own settings
  live in their home directory, not in this repo.

Apps publish to the public reference repo unless they are proprietary (see
`registry/mirror.yaml`), so the scrub rules apply: no personal names, machine names or client names.
